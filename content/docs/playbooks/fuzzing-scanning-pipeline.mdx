<Callout type="info" title="Playbook">
  This recipe chains five separate CLI tools — [Chaos](https://github.com/projectdiscovery/chaos-client),
  [HTTPX](https://github.com/projectdiscovery/httpx), [Naabu](https://github.com/projectdiscovery/naabu),
  a [naabu-to-nmap](https://github.com/SAERANGAM/naabu-nmap) wrapper, and
  [nmap-parse-output](https://github.com/mrschyte/nmap-parse-output) — into
  one pipeline. See the [Nmap](/docs/port-scanning/nmap) page for Nmap's own
  flag reference.
</Callout>

A recon pipeline for going from "list of subdomains" to "annotated Nmap
results" — each step's output feeds the next tool.

<PageVariables vars={{ target: "domain.com" }} />

## Step 1 — Find all IPs behind a domain ([Chaos](https://github.com/projectdiscovery/chaos-client))

<PageCommand
  derivedVars={{
    chaos_filename: { from: "target", template: "chaos_{value}.txt", shared: true },
  }}
  command={`chaos -d {{target}} -o {{chaos_filename}}`}
/>

Chaos queries ProjectDiscovery's dataset of internet-wide DNS records to
return known subdomains/IPs for a domain.

| Flag | Meaning |
| --- | --- |
| `-d <target>` | Target domain. |
| `-o <file>` | Save results to file. |

## Step 2 — Filter to active hosts, extract IPs ([HTTPX](https://github.com/projectdiscovery/httpx))

<PageCommand
  derivedVars={{
    ip_filename: { from: "target", template: "httpx_{value}.txt", shared: true },
  }}
  command={`httpx-toolkit -l {{chaos_filename}} -ip -silent | sed -nE 's/.*\\[([0-9.]+)\\].*/\\1/p' > {{ip_filename}}`}
/>

| Flag | Meaning |
| --- | --- |
| `-l <file>` | Input list of hosts to probe. |
| `-ip` | Include the resolved IP address in the output. |
| `-silent` | Suppress banner/noise, print clean results only. |
| `sed -nE 's/.../\1/p'` | Regex extracts just the IP address from inside the brackets HTTPX prints. |

## Step 3 — Deduplicate IPs

<PageCommand
  derivedVars={{
    ips_filename: { from: "target", template: "ips_{value}.txt", shared: true },
  }}
  command={`cat {{ip_filename}} | sort -u > {{ips_filename}}`}
/>

`sort -u` sorts the list and removes duplicate entries.

## Step 4 — Find open ports ([Naabu](https://github.com/projectdiscovery/naabu))

<PageCommand
  derivedVars={{
    naabu_filename: { from: "target", template: "naabu_{value}.txt", shared: true },
  }}
  command={`naabu -l {{ips_filename}} -top-ports 100 -rate 1500 -verify -silent -o {{naabu_filename}}`}
/>

| Flag | Meaning |
| --- | --- |
| `-l <file>` | Input list of IPs to scan. |
| `-top-ports 100` | Only scan the 100 most common ports (fast). |
| `-rate 1500` | Packets per second to send — controls scan speed. |
| `-verify` | Do a TCP verification pass on found ports to reduce false positives. |
| `-silent` | Clean output for piping. |
| `-o <file>` | Save results to file. |

## Step 5 — Enrich with Nmap ([naabu-to-nmap](https://github.com/SAERANGAM/naabu-nmap))

<PageCommand command={`python3 naabutonmap.py -i {{naabu_filename}}`} />

A multi-threaded Nmap wrapper that takes Naabu's open-port list and runs
Nmap's deeper service/version detection against each host:port pair,
consolidating everything into a single report instead of running Nmap
manually per host. It doesn't document its own output-filename flag — it
writes an `nmap_out.xml` alongside the input by default (see the tool's own
`-h` output for options).

| Flag | Meaning |
| --- | --- |
| `-i <file>` | Input file — Naabu's scan results. |

## Step 6 — Format the results ([nmap-parse-output](https://github.com/mrschyte/nmap-parse-output))

<PageCommand
  derivedVars={{
    report_filename: { from: "target", template: "report_{value}.html" },
  }}
  command={`./nmap-parse-output
./nmap-parse-output nmap_out.xml html > {{report_filename}}`}
/>

A modular Nmap XML post-processor that uses XSLT-based commands to extract,
transform, and format scan results — here, into a browsable HTML report.

| Argument | Meaning |
| --- | --- |
| `<nmap_out.xml>` | Nmap's XML output file (use `-oX` when running Nmap to produce this). |
| `html` | Output format command — converts XML into an HTML report. |
| `> page.html` | Redirects the generated HTML into a file. |
