<Callout type="info" title="Decision guide">
  This page doesn't introduce new commands — the commands for every option
  below live on their dedicated tool pages. This page only summarizes when
  to reach for each one.
</Callout>

Two tools for brute-forcing hidden directories/paths on a web server, plus a
content-based filtering trick for sites with a fake/custom 404 page.

## Gobuster

The simpler option — single-mode directory brute-force, good default choice
when you don't need response filtering beyond status codes.

See the [Gobuster page](/docs/web-fuzzing/gobuster) for the command and full
flag reference (DNS mode is covered separately on the
[Subdomain & Attack Surface Discovery](/docs/subdomain-discovery/gobuster-dns)
page).

## FFUF (length/status-based)

More configurable than Gobuster: custom headers, tunable
concurrency/rate-limiting, and multiple status codes matched in one flag.

See the ["Directory / sub-path fuzzing" section of the FFUF page](/docs/web-fuzzing/ffuf)
for the command and full flag reference.

## FFUF (content-based filtering — for sites with a fake 404 page)

<Callout type="info">
  Before using this, check what the site's fake-404 page actually says.
</Callout>

Many apps return `200 OK` with a custom "not found" page instead of a real
HTTP 404, which breaks naive status-code/length filtering. FFUF's `-fr` flag
filters out any response whose **body** matches a given string/regex,
regardless of status code or length.

See the ["Content-based filtering" section of the FFUF page](/docs/web-fuzzing/ffuf)
for the command and full flag reference.

<Callout type="warn">
  Always check for a custom/fake 404 page before relying on status-code or
  length-based filters — content-based filtering with the exact fake-404
  body text is the most reliable approach in that case.
</Callout>
