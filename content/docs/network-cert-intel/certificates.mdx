Inspecting the TLS certificate a server presents — issuer, validity dates,
Subject Alternative Names (SANs), and chain — often reveals internal
hostnames or related infrastructure not advertised anywhere else.

## Quick CLI equivalent

#### View a site's certificate details

<CommandInput
  vars={{ domain: "domain.com" }}
  derivedVars={{ output: { from: "domain", template: "openssl-cert_{value}.txt" } }}
  command={`openssl s_client -connect {{domain}}:443 -servername {{domain}} > {{output}}`}
  placeholderMode
/>

| Flag | Meaning |
| --- | --- |
| `s_client` | Subcommand: connect to a server as a TLS/SSL client and print the handshake/certificate details. |
| `-connect <host>:443` | Host and port to connect to. |
| `-servername <domain>` | Sends SNI (Server Name Indication) — required to get the right certificate from hosts serving multiple domains off one IP (virtual hosting, CDNs). |

<Callout type="info">
  [Censys Search](/docs/network-cert-intel/ip) also indexes certificates
  across the internet — useful for finding every host presenting a specific
  certificate, not just the one you're pointed at directly.
</Callout>

See [Cipher Suites](/docs/network-cert-intel/cipher-suites) for auditing the
negotiated TLS protocol versions and ciphers instead of the certificate
itself.
